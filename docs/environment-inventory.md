# 环境调查（公开脱敏版）

调查日期：2026-10-20。通过用户授权的设备插件执行只读命令，未根据目录名推断实际版本。

| 项目 | 实际观察 | 结论 |
|---|---|---|
| NAS | Linux x86_64，有现有 Docker 环境 | 新建独立镜像、容器与数据目录，不复用旧项目数据 |
| Windows | Windows 11 Pro，10.0.26200，64 位 | 设备名称不代表 Windows Server 产品版本 |
| MAA | 文件版本与产品版本均为 6.20.0 | 安装目录名保留旧版本号，不能据其判定版本 |
| 配置 | `config/gui.new.json`，多个 `Configurations` / `TaskQueue` | 一个 MAA 安装对应多个配置档；不是两个独立进程 |
| 旧配置 | `config/gui.json` 仍存在，内容结构不同 | 当前只读适配器优先读取已验证的新结构，不回写旧配置 |
| 两个配置档 | 独立启动账号标识、任务顺序、库存计划与基建文件 | 分别绑定并读取，禁止互相复制覆盖 |
| MuMu | 两个配置档指向同一模拟器连接 | 不能假设允许并行执行或已完成账号切换 |
| 定时 | MAA 自身已有启用的定时配置 | Web 自动调度关闭，原定时不变 |
| 仓库 / Box | 安装目录存在 DepotData 与 OperBox 缓存；缓存未标明可验证的账号归属 | 不归属到任意账号，不伪造实时库存 |
| 其他程序 | 另有 MaaEnd 与其定时任务 | 独立程序，不当作 MAA 控制或修改 |

真实账号、配置路径、机器地址、配置原件、哈希清单及部署凭据只保存在私有部署目录，不提交到公开 Git。

未完成的现场能力验证见 [能力矩阵](maa-capability-matrix.md)。本文件不证明尚未接入的任务控制或配置写入能力。
