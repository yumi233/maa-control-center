# Agent 配置模式与通知

## 使用流程

1. 登录网页，打开 **Agent 配置 → 接入与通知**。
2. 填写 API 基址（例如服务商给出的 `/v1` 地址）、完整且确切的模型标识、API Key，保存并测试。服务需支持 Chat Completions 的 JSON object 响应；高级兼容选项可明确选择 `max_completion_tokens` 或 `max_tokens` 输出限额参数；不自动替换模型或切换服务商。
3. 回到配置助手，选择账号与修改范围，输入具体需求。示例：“公开招募最多执行 4 次，其他设置不变”。
4. 核对逐字段原值和建议值。确认后由 Windows 等待空闲、正常关闭 MAA、备份并写入，再用禁止启动自动执行的参数重载。运行中的游戏任务不会被强制终止。
5. 勾选确认并应用。Windows 再次检查本地账号规则、版本、进程、指纹，备份原文件，原子替换并重新读取校验。查看修改记录中的最终回执。
6. 如需恢复，在记录中选择“预览回滚”，核对反向差异后再次确认。只有当前文件仍与该次应用结果一致时才恢复，后续人工修改不会被覆盖。

管理员首次主动测试模型或生成方案会调用自己配置的 API，可能产生服务商费用。开发验收只使用本机模拟 HTTP 服务；没有替用户挑选、调用或升级任何真实模型。

## 规则库

机器可读规则是 [`internal/rules/catalog.json`](../internal/rules/catalog.json)，版本 `maa-6.20-r2`。字段名称依据 [MAA v6.20.0 官方配置定义](https://github.com/MaaAssistantArknights/MaaAssistantArknights/tree/v6.20.0/src/MaaWpfGui/Configuration/Single/MaaTask)，本项目没有链接或打包 MAA 程序。

| 范围 | 可修改内容 |
| --- | --- |
| Fight | 启用、资源使用及预算、掉落目标、次数、关卡列表、临期药设置等已列字段 |
| DepotMaintain | 启用、补货排序、活动跳过、临期药、计划新增、删除、排序及现有计划的关卡/目标/资源预算 |
| Recruit | 招募次数、星级、加急、刷新、标签、保留凭证与招募时长 |
| Mall / Award | 信用收支、商店偏好、奖励与邮件开关 |
| Infrast | 已核实的宿舍、线索、无人机与排班选择等设置 |
| 任务排序 | 原任务对象的完整排列，开始唤醒保持首项；单独预览确认 |
| 排班文件 | 现有班次房间的干员、候选干员和跳过标志 |

不接受任意 JSON 路径、整文件替换、命令、脚本、下载或模型工具调用。账号身份、ADB、路径、凭据、原通知和远程控制设置受保护；原有定时只能经单独的 timers 规则调整本配置档已分配项目的开关和时间。未列字段与未核实版本保持只读；不声称覆盖所有历史和未来 MAA 功能。

副号的最终配置独立检查：普通药和源石的有效预算必须为 0，已启用作战保留 48 小时临期策略；禁用的作战任务也检查，防止以后启用时绕过。主号与副号的对象不合并。未知字段及大整数保留语义；字段回滚优先生成原值的逆向方案，避免覆盖 GUI 自行更新的运行字段；结构修改的整件备份恢复需要完整指纹一致。排班被其他配置档共用时拒绝修改，避免串号。

规则只验证配置结构及安全边界。关卡当天是否开放、干员是否持有、登录是否切换成功、游戏里是否执行成功仍需实际核实。Windows 在确认空闲并正常退出后写入；避免同时用其他编辑器修改同一文件。

## Windows 启用同步

原 Agent 配置新增以下选项，默认不写文件：

```json
{
  "allow_config_write": true,
  "state_dir": "C:\\MAAControlCenter\\agent-state",
  "profile_roles": {
    "your-primary-profile": "primary",
    "your-secondary-profile": "secondary"
  }
}
```

合并到已有私有配置，保留已有服务器、令牌、MAA 目录和允许读取目录。键使用实际配置档 ID。此开关只允许接收经网页确认的方案，不会自行生成或应用方案。Agent 状态目录及备份包含配置原件，需要限制为当前运行用户、SYSTEM 和管理员可读写。不要放进公共目录或 Git。

方案有效期 10 分钟。两个阶段都核对源文件 SHA-256；规则在 NAS 和 Windows 各执行一次。实例锁、排他备份与持久化操作意图阻止并发重复写入。中断后结果未知时不自动再次修改；检查本地回执、备份及文件，确认后再处理残留锁。文件替换与 GUI 启动无法形成跨程序事务，异常中断时保留备份与 unknown 状态，禁止盲目重复执行。

## 挂机通知与账号范围（0.4.4）

各通知渠道的「接收账号」可选择全部或指定账号。筛选依据账号 ID，改备注后继续生效；未核实账号归属的实例通知不发给限定账号的接收端。主动连接测试可单独发送。控制中心改备注不改游戏登录、MAA 配置档或资源预算。

托管日常任务首次返回 `running` 时发送开始通知，完成、失败或确认停止时发送结束通知。事件与状态在同一事务写入，重复回执不会重复入队。配置检查不发挂机通知。

结束通知只读取本次时段的 MAA 回调与 GUI 任务结束日志：

- 理智注明实际读数及时间。日志完整且读数后没有作战开始或结算时，附上仅按每 6 分钟自然恢复的估算与预计回满时间。估算不是结束时实测，不推断药品、源石或实际理智消耗。
- 关卡显示结算记录数；掉落只累加 [StageDrops 当次 drops](https://docs.maa.plus/zh-cn/protocol/callback-schema.html)，不累加累计 stats。任务结束不保证所有目标完成或奖励全部领取。
- 「今天」按北京时间结束日期、原任务所属用户与账号隔离，包含当前这一轮。最多聚合最近 100 轮明细，缺失或不完整情况会注明。
- 日志缺失、截断、旧版 Agent 或任务未实际开始时，明确显示未采集，不额外打开游戏。

明细存于 `job_activity`，有权限的用户可通过 `GET /api/v1/jobs/{id}` 查看 `activity`。同一终态、同一结束时间的 Agent 回执可补录一次缺失明细，保留原结果和通知，不重新发送。

## Telegram

通过 BotFather 创建 Bot，先与 Bot 发起聊天，或将其加入目标群并授予发言权限。在网页填写 **Bot Token、Chat ID**，启用并保存，再点“发送测试消息”。Bot 的权限和目标由用户自己的 Telegram 设置决定。

服务端使用 [Telegram Bot API sendMessage](https://core.telegram.org/bots/api#sendmessage)，固定请求官方 HTTPS 地址；不使用 Markdown/HTML 解析用户文本。NAS 必须能连接 Telegram 网络。密钥不进入消息、网页读取响应或普通错误日志。

## QQ 官方机器人 / AstrBot

通知支持通过 [AstrBot HTTP API](https://docs.astrbot.app/dev/openapi.html) 直连已经接入的 QQ 官方机器人。在 AstrBot 设置中创建仅有 `im` 权限的 API Key，将 AstrBot 基址（例如 `http://192.168.1.2:6185`）、Key 和目标会话完整 UMO 填入「我的接入与通知」。UMO 来自目标机器人私聊或群聊中的 `/sid`，格式为 `平台:FriendMessage:会话标识` 或 `平台:GroupMessage:会话标识`。UID 用于 AstrBot 管理员配置，通知路由使用 UMO。

保存并启用后，使用该渠道的单独测试按钮核验发送。请求为 `POST /api/v1/im/message`，Bearer 认证，正文为 `umo` 和纯文本 `message`。通知测试不调用模型；实际任务通知继续沿用已保存的表达偏好。接入不修改 AstrBot 的管理员、白名单、现有机器人或模型配置。

旧版本升级时新增的 AstrBot 渠道默认禁用，原有 TG、OneBot 和密钥保持原值。内网地址仍仅允许管理员显式授权。`sent` 表示 AstrBot 接口确认处理，不代表用户已经阅读；QQ 官方平台的主动推送额度、时段和权限限制需结合实际回执核验。无法确认送达的结果标为 `unknown`，不会自动重发。

## QQ / OneBot / NapCat

使用自己已有的 OneBot v11 HTTP 服务，在网页填写其地址、Access Token、私聊或群聊与目标号码。明文 HTTP 仅允许用户显式勾选后的内网 IP；公网服务要求 HTTPS。随后保存并测试。

实现采用 [OneBot v11 公共 API](https://github.com/botuniverse/onebot-11/blob/master/api/public.md) 的 `send_private_msg` / `send_group_msg`，访问令牌使用 Bearer 头，正文使用 text 消息段，避免把文本当 CQ 指令。无需修改 MAA 原有外部通知设置，也不会自动安装或接管 QQ 客户端。

## 消息内容与可靠性

通知包含对象、状态、时间、详情、证据来源和记录 ID。配置应用依据 Windows 回执，MAA 队列结束依据已核实的中文 GUI 日志标记；进程退出、普通 SUCCESS 或任务链局部完成都不作为整个队列完成。

MAA 6.20 中文队列日志的成功和带错结束分别处理。日志无法确认账号归属时明确写出“账号归属未核实”，不根据当前配置档猜测。首次启用监听之前的历史日志不推送。监听读取最近 256 KiB 日志；异常长时间断线且日志已轮转时可能漏报，当前不提供完整历史补发保证。其他语言或未知日志格式暂不识别。

可勾选 **Agent 通知语气**。模型根据状态为受控的开场文案选择语气；事实摘要由程序固定生成，模型不修改成功/失败、资源、数量或时间。模型失败退回普通模板，不影响通知发送。实现刻意不允许自由生成事实，以免把带错结束润色成成功。

通知先保存到持久化发送队列，同一事件与渠道只入队一次。接口确认后标为“渠道已接收”，这不等于用户已阅读。超时、异常响应或服务端错误可能已送达，此时标为“待核实”，不盲目重发。用户核实收件端后才能手动重试，重试提示可能重复。

## 密钥、备份与升级

API Key 与通知令牌使用 AES-256-GCM 加密后存进 SQLite；密钥文件是数据库同目录的 `integrations.key`（0600）。页面 GET 只返回是否配置，留空保留密钥，明确选择清除才删除。数据库和配套加密密钥文件要一起做私有备份；丢失密钥不能恢复已保存凭据。

从 v0.1 升级会新增表，不改写现有 MAA 文件。先停止自己的管理中心容器、备份数据库与 `integrations.key`（如存在），再升级服务端和 Agent。回退管理中心程序使用升级前的数据库副本与二进制；这与 MAA 配置回滚是两个独立操作。

OpenAI 兼容接口的 JSON 模式只保证 JSON 格式，不能代替字段校验；参考 [官方结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。本项目在模型输出之后始终执行自己的闭合规则，并检查返回的模型标识与用户指定型号一致。
