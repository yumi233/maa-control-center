## 真实设备部署验证（2026-10-20）

- NAS 独立容器已启动：非 root 用户、只读根文件系统、独立 SQLite 数据目录、局域网 HTTPS 监听、自动重启与日志轮转。
- 使用私有 CA 进行完整证书校验，健康接口返回 200；未登录账号接口返回 401；登录 Cookie 含 Secure / HttpOnly。
- Windows Agent 二进制与 NAS 二进制均对照发布的 SHA-256 验证。两端均保存对应版本源代码。
- Windows 当前用户的独立登录任务已注册并处于运行状态；后续真实心跳时间持续更新。未通过重启整机测试登录触发器。
- 实际读取两个独立配置档，任务数量分别为 7 / 6，库存目标分别为 23 / 25；基建 JSON 独立且哈希不同。
- 副号现有有效资源策略核对为普通药剂 0、源石 0、临期药 48h。当前库存未确认归属，API 保持 null。
- 四份关键 MAA 配置部署前后 SHA-256 完全一致，现有 MAA 定时配置未写入。
- 新服务重启后，两个账号绑定和读取数据保持；没有生产任务产生，也没有下发资源消耗指令。
- 新服务的一致性数据库备份通过 SQLite integrity_check；恢复到隔离的内存数据库后再次返回 ok，两个账号绑定均存在。
- GitHub 公开仓库确认识别 MIT，项目主题已设置；分支与版本标签的 GitHub Actions 构建均成功。

实际路径、地址、原件、哈希清单与登录信息仅留在私有部署目录。上述验证只覆盖只读 MVP，不代表后续控制阶段已经完成。

## 当前限制

- v0.1 是能连接真实 Agent 的只读 MVP。实际任务启动 / 停止、截图、配置同步、自动调度、策略应用与搓玉切换没有启用。
- 库存目标可读；现有共享仓库 / Box 缓存尚未确认账号归属，当前库存保持未知。
- MAA 进程存在只能证明进程存在；没有官方任务心跳时显示 unknown，而非 running。
- 生产日志仅是实例级文件尾，不假定每行都属于当前展示账号。
- 多用户权限、生产任务互斥锁、完整调度器和配置版本回滚属于后续阶段；数据库结构预留不等于实现完成。
- Agent 当前适配的是已观察到的 6.20 新 GUI 配置。其他结构拒绝推断，不写入原件。
- HTTPS 初始使用本机生成的私有 CA。浏览器需明确安装公有 CA 证书或改用用户自己的受信任证书。
