# 多用户与访问权限

v0.3.0 提供管理员邀请制，没有开放注册。首次升级保留现有管理员密码；已有主号、副号及绑定归现有管理员所有。启动配置中的初始密码只用于第一次创建管理员，不会覆盖数据库中的密码。

1. 管理员在「用户管理」创建用户，设置初始密码及成员或管理员权限。
2. 在「MAA 账号」添加账号记录，选择所属用户、名称和资源策略。
3. 在账号详情的「实例绑定」中，由管理员选择 Windows Agent 实际发现的配置档。一个配置档只能绑定一个账号；新增 Windows 配置档的受控写入仍需在 Agent 本地明确允许对应策略。
4. 成员登录后，只能查看和修改自己名下的账号、配置预览及历史。成员也可以添加自己的待绑定账号记录，再由管理员完成配置档绑定。

成员不能浏览未分配的设备发现结果，也看不到共享 MAA 进程中无法确认账号归属的日志。成员的模型密钥、通知接收目标和送达记录分别保存，密钥加密且不能从网页读回。成员不能启用对内网模型或 OneBot 地址的访问；内网服务由管理员配置和使用。实际队列结束日志尚不能核实属于哪个账号，因此仅通知原始管理员，不会向各成员群发或推断任务归属。

所有账号读取、预览、确认、取消、回滚和通知重试都在服务端检查权限。账号转交会取消旧预览；有待执行、正在处理或结果待核实的方案时，必须先处理这些方案才能转交。停用、降级或重置用户密码会撤销其登录并取消尚未下发的相关方案。已经在 Windows 处理的操作需要接收真实回执，不能宣称已撤销。

「系统设置 → 修改登录密码」要求输入当前密码及两次新密码。密码长度为 12–72 字节。成功后所有原登录立即失效。管理员可以为其他用户重置密码；不能在当前登录中停用或降级自己，并保留至少一个可登录管理员。

升级先备份 SQLite 数据库和配套 `integrations.key`。迁移原子提交并记录版本；重复启动不会再次迁移或重设密码。旧版通知中送达不确定的记录不会自动重试。

# 通知排错

运行镜像需要系统 CA 证书包及有效 DNS。官方 Dockerfile 在构建阶段安装证书，并复制到最终轻量镜像。手工制作镜像时也应加入 `/etc/ssl/certs/ca-certificates.crt`。如果宿主机 DNS 仅监听本地或依赖容器不可达的链路本地地址，为这些容器配置可达的 DNS，不修改整个 NAS 的其他服务。

Telegram 需在私聊中先对机器人发送 `/start`；群聊需添加机器人并使用正确群 ID。Bot Token 不同于 Chat ID，群 ID 通常为负数。支持数字 Chat ID 或公开频道的 `@频道名`。

连接、DNS 和 TLS 在请求写出前失败会记录「发送失败、尚未发送」；请求发出后失去确认则保留「结果待核实」。Token 无效、机器人被屏蔽、Chat ID 不存在及限流会给出对应提示。未知结果不自动重发；核实收件端后可以人工重试。Telegram 确认 API 接收不等于人已阅读消息。
