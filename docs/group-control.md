# 群控、成员与新账号接入

## 授权关系

网页用户拥有账号；账号绑定 Windows Agent 的一个 MAA 配置档；群控接入只授权一个账号和一个完整 UMO。群成员以 `/sid` 返回的 UID 识别，不用昵称、QQ 数字或群号推断身份。每个接入有独立密钥，数据库只保存其 SHA-256，不复用网页登录密码、Agent 配对密钥或 AstrBot 推送密钥。

| 身份 | 可执行操作 |
| --- | --- |
| 网页管理员 | 新建用户、账号、分配归属，管理接入 |
| 网页账号主人 | 管理自己的群控接入、授权成员与账号设置 |
| 群成员：仅查看 | 状态、任务汇报、今日记录、定时计划 |
| 群成员：可启停任务 | 以上操作，并可开始或请求停止绑定账号 |
| 未授权成员 / 其他会话 | 不可查询或控制 |

群指令不提供预算修改、资源充值、任意命令、成员提权、账号转交或定时修改。开始只执行现有已启用任务；停止等待 Windows 的实际空闲回执，不把“请求已接受”说成已经停止。重复的平台消息 ID 不重复创建任务，账号有活动或待核实任务时拒绝叠加；超时不自动重试。

## 给已有群增加成员

1. 新成员在机器人里发送 `/sid`，把 UID 交给账号主人。UMO 用来绑定会话，UID 用来授权个人，两者不能互换。
2. 账号主人打开 **Agent 配置 → 群聊控制 → 已授权接入**，在正确账号下点“添加成员”，填写 UID、备注，默认“仅查看”。需要操作的人再选“可启停任务”。
3. 保存成员权限，无需重新安装插件或发密钥。后台按每次请求的最新权限核对，过期页面的编辑会拒绝覆盖新变更。
4. 撤权时移除该成员并保存。撤销整个接入会使原密钥失效。撤权不自动停止已提交任务，账号主人需要时在网页请求停止。

群成员无须拥有网页登录账号。需要独立网页工作区的人，再由管理员创建网页用户并分配账号；不要为了 QQ 控制给成员全站管理员权限。

## 添加新游戏账号

1. 管理员添加账号，填写清晰的姓名或备注，确定归属：自己代管可继续归现有用户；需要对方独立网页登录时创建普通网页用户再分配。
2. 在 Windows MAA 中准备独立配置档和游戏登录信息；由设备管理员把新配置档 ID 加入 Agent 私有配置的 `profile_roles`，明确主号或副号保护角色，再刷新发现并在网页绑定 Agent、实例和配置档。只在网页添加账号不会扩张 Windows 的执行白名单。不要复制别人的登录凭据。完成配置档切换检查后再安排真实挂机。
3. 核对该账号原有任务、药品、源石和临期药预算。副号保护规则照常生效，复制计划或绑定群控不会自动修改预算。
4. 在“任务与定时”创建该账号的计划。同一 Windows 实例继续串行执行；检查游戏切号能力并避开保留的原生 MAA 定时重叠。新账号不会自动继承其他账号的四条现有计划。
5. 配置通知：在账号主人的接入设置选择接收端与账号范围。新建群控不等于启用推送；原群只接收指定账号时继续保持该范围。普通用户仍不能自行请求内网服务；内网 AstrBot 由管理员代管，独立用户接入使用已授权的公网 HTTPS 服务。
6. 为新账号建立独立群控接入，添加需要的成员。推荐独立群；需要同群多账号时合并插件配置的 `routes`，每条保留自己的密钥，并在指令中明确账号备注。

账号转交时必须没有活动或待核实任务。系统会停用原定时并撤销旧群控接入；新主人重新核对配置、通知和成员后再授权，不继承旧操作者。

## 安装 AstrBot 接收指令

插件源码位于 [`integrations/astrbot_plugin_maa_control`](../integrations/astrbot_plugin_maa_control)，按 [AstrBot 官方插件方式](https://docs.astrbot.app/dev/star/plugin-new.html) 安装。插件不调用模型，不执行 Shell，也不创建额外调度器。

在网页创建接入后下载一次性私有配置，保存为 AstrBot 的 `data/plugin_data/maa_control/connection.json`。内网 HTTPS 把控制中心 CA 放进同目录，并在 `ca_file` 填实际路径；不要关闭证书验证。文件只允许机器人运行用户和管理员读取，不提交 Git 或发送到群里。配置新增路由后下一条指令即会重新读取；成员修改只需网页保存。

一个配置可有多条 `routes`，每条包含 `umo`、`account_id`、`label` 和该绑定独立 `token`。同一会话中账号不唯一时，省略账号的指令会拒绝执行。同名账号请使用账号 ID，避免歧义。后台再次核对会话、账号、UID、权限、账号归属与消息时间。

也可由服务器管理员使用 `maa-bot-bind-linux-amd64` 创建第一个接入。使用 `--db` 指向已经迁移的数据库，`--owner`、`--account`、`--umo`、`--uid` 指定范围，`--server` 指定 HTTPS 地址，`--ca-file` 填 AstrBot 看到的 CA 路径，`--output` 写入不存在的私有文件。工具不打印密钥，不改变密码或游戏配置。后续成员通过网页维护。

## 指令

| 指令 | 行为 |
| --- | --- |
| `/maa 帮助` | 当前接入的用法 |
| `/maa 状态 [账号备注]` | 设备连接与活动任务 |
| `/maa 开始 [账号备注]` | 将当前配置加入队列，不改变预算 |
| `/maa 停止 [账号备注]` | 取消待执行任务，或请求 Windows 停止活动任务 |
| `/maa 汇报 [账号备注] [任务ID]` | 最近一次或指定任务的真实结束汇报 |
| `/maa 今日 [账号备注]` | 北京时间当天该账号的执行记录 |
| `/maa 计划 [账号备注]` | 查看已有定时，不修改它 |

单账号群可省略账号，`/maa 汇报 任务ID` 也可直接查询。QQ 官方机器人通常需要在群内 @ 机器人。收到“未确认”先查状态，不连续重发启停；报告里的理智估算、日志覆盖率和结算记录仍遵守 [通知说明](agent-mode.md)。

## 验收与边界

自动检查覆盖成员角色、错误群/UID/账号、过期消息、重复并发请求、账号串行、真实停止回执、撤销、移交和事务回滚。部署核对插件载入、真实后端只读查询、既有任务明细与预算基线。主动推送以 AstrBot/QQ 返回为准；完整群内交互仍需真实群成员发起消息，游戏任务仍须观察 Windows 与 MAA 真实结果，不能用模拟测试替代。
