# 配置与多账号定时（v0.4）

## 直接修改配置

在「MAA 账号」点击「编辑配置」，或打开「配置编辑」选择账号。可编辑规则库覆盖的任务开关、招募、信用收支、资源预算、库存目标及顺序、独立基建排班干员和原有定时。无需模型 API。

修改 → 预览并保存修改 → 核对每项原值与新值 → 勾选确认 → 确认保存并重载。Windows 等待空闲后正常关闭 GUI，保留本地备份，验证文件和差异，原子写入并读回，再以 `--skip-startup-auto-run` 重载。保存本身不点击游戏开始。

「保存结果推送通知」可单独选择，默认关闭。记录中能看到等待、应用、冲突和失败原因。字段修改可预览回滚，仍需确认；结构调整在 GUI 修改源文件后可能需要人工使用本地备份恢复，不能强行覆盖。

普通运行状态字段的变化不再导致永远冲突：完整文件指纹变化时，只有同一配置档的可编辑投影仍与预览一致，才允许重新计算并合并。业务字段变动依然拒绝。排班共享文件拒绝跨账号写入，未知字段保留。

## 多账号每日 / 每周计划

打开「任务与定时」，选择账号、名称、北京时间与星期，创建计划。可以暂停、编辑、删除。支持同一账号多个计划、不同账号不同计划；所有任务在同一 Windows Agent 上顺序执行，防止共用模拟器时并发切号。

到点写入持久队列；超过十分钟的漏触发记为错过，不补跑整段停机期间的任务。已排队任务一小时后过期。未连接的设备会等待连接，启动前再次核对用户、账号绑定、配置档、规则和本地角色。转移账号会停用旧归属的计划，成员无权查看或操作其他成员的任务。

原有 MAA 的八个定时槽继续由 MAA 自己执行。页面显示它们并可跳转调整。强制定时可能打断网页任务；使用新计划前应主动安排互不重叠的时段。检测到原生定时介入时，网页执行标为待核实，不冒认是本次队列完成。

## 手动执行与状态

「运行已启用的游戏任务」会选择对应 MAA 配置档，然后调用原生 Link Start!。配置档必须已有有效开始唤醒账号和自动切换设置；不会代填游戏账号。MAA 是否成功登录与游戏是否通关须依据实际日志和游戏结果。

「仅检查配置切换与 MAA 界面」只切换配置档并检查空闲窗口，不点击开始、不验证游戏内切号，也不推送任务完成通知。

请求停止后保持「等待停止确认」，确认界面空闲后才释放占用。重启、进程替换或不确定的启动记录转为「结果待核实」，不会自动再次点击开始。核实后可请求 Windows 检查空闲并解除占用。

## Windows 条件

在私有 Agent 配置中启用 `allow_config_write`、`allow_task_control` 并填写 `profile_roles`。使用当前用户 Limited / Interactive 登录任务，保持该用户已登录；Windows 6.20 MAA 原生窗口是适配对象。未确认窗口状态时排队等待，不强杀进程。MAA 其他版本或第三方窗口不冒用已验证状态。

完成提示依据本次新产生的完整队列结束标记，并结合所属进程、当前配置档和空闲界面判断。带错误结束单独标记；普通 SUCCESS、启动接受或单一子任务结束不能作为整个游戏队列成功。
